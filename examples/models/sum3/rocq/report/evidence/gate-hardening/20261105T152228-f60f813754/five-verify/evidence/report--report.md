# Reference artifact gate hardening

The old metadata validator could accept an unrelated successful kernel command found anywhere under an active attempt. It did not bind that command to the current `Proof.v`, canonical `Spec.v`, requested goal or actual compiled source snapshot. It also silently ignored the published `artifacts` input layout and the relation `files` provenance index. That was a validator assurance gap; it does not establish that the existing Rocq proofs are invalid.

The active evidence gate now requires `five-proof-validation/1`: an explicit retained index adapter, current source hashes, exact source-to-compiled-snapshot mappings, canonical kernel receipts, actual compilation of every recorded dependency and consistent logical module mappings. Duplicate namespace mappings fail. Every requested goal is instantiated in a deterministic additional `GoalBinding.v`, compiled by Rocq with `Print Assumptions`, and independently kernel checked. The original proof bodies and specification/model files remain unchanged. Historical receipts and historical configurations remain historical; they are not silently relabeled as current verification.

The sum3 aggregate request “all ten original emitted CBMC properties” is expanded to its exact ten existing property IDs, preserving the same scope and the three supplemental requested goals. The existing canonical CBMC gate still checks original property IDs, conditions, theorem receipts and execution bindings.

Reproducible disposable metadata fixtures: `python3 -m unittest discover -s scripts/tests -v`. Twenty-two tests cover a passing bound fixture, Proof/Spec substitution after superficial hash refresh, changed goals/types, nonexistent or unrelated theorem receipts, missing/empty/malformed indexes, all five published index layouts and pinned external semantic hashes, missing dependency compilation or certificate input snapshots, wrong/duplicate module mappings, unchecked kernel options, help-only compilation, compiler output overrides and absent assumptions output. Fixture receipts are deliberately synthetic metadata for testing the validator; they do not claim a real proof run. The seven reference cases use separate genuine Rocq compilation/kernel evidence.

This gate checks the chain from recorded user goals and source artifacts to actual typed theorem certificates and kernel receipts. Human review still determines whether the requested formal propositions express the intended C/CompCert behavior. A valid unrelated theorem is not evidence for the requested proposition.

Shared validation work is measured under [the own-actor five-verify run](20261105T152228-f60f813754/five-verify/run.json), using the verified actor session and [actual runtime metadata](runtime-metadata.json). The observed runtime is gpt-6.1-sol with medium reasoning effort. The boundary starts before substantive edits, after initial read-only inspection and session discovery. This is shared metadata assurance work across all seven examples, not a new sum3 proof or an arbitrary per-case allocation. Gold goal-certificate generation has its own measured run. Tool CPU/RSS cover recorded commands, not the surrounding host/IDE or unrecorded exploratory reads; token events use the actual own-session event boundary. Raw telemetry is retained unchanged.

Normalized shared validation figures and scope are retained in [costs.json](costs.json); the underlying run is independently checked by `scripts/audit-costs.py`. Genuine certificate generation is reported separately by its actual proof worker.
