# Independent current-proof binding review

The former validator accepted any successful kernel command and failed to bind the current proof, canonical specification and requested goal to the actual compiled module. The original six metadata fixtures missed this central invariant; their success did not justify proof-backed assurance.

After the strict gate and genuine typed certificates were installed, an independent full real-tree Validator.run accepted all seven active problems. Seven in-memory substitutions were rejected for their intended binding reasons: unrelated True proof despite refreshed index/current-binding/outer-handoff hashes; weakened True specification with the same refresh; unrelated successful kernel receipt; renamed requested goal; missing input bindings; wrong goal type and rewritten certificate source/hash with genuine old compiler receipt retained; nonexistent theorem within a successfully checked module.

See [exact results](results.json), [test source](independent-attacks.py), and the original [actual command run](run/run.json). These tests changed no canonical files. All seven proof/certificate dependency closures were separately freshly compiled and independently kernel checked in the sibling construction run. Actual original proof declarations and intended conditions were reviewed; no original theorem defect was identified.

The original substitution gap is closed for this tested stale-artifact/substitution model. This is bounded validation evidence, not a universal proof of validator correctness or resistance to forged raw execution receipts. Costs and actual medium runtime configuration are recorded here without overlap with the construction stage; raw run telemetry is preserved unchanged.
