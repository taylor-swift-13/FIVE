# 命令限幅放置位置比较

本问题固定原始 `guidance_pid_h_run_pos` CompCert模型。比较对象只改变命令限幅的位置，所有定点取整、输入误差夹持、前馈、增益与PD积分更新保持完全相同。

令 `A` 为已按原整数右移计算的 **PD与速度/加速度前馈总量**（准确表达式由 `total` 固定），`I'` 为原程序更新并限幅后的积分，`b=floor(I'/65536)`。实际算法和统一限幅参考分别为

```
two = clip(3216, clip(1429, A) + b)
one = clip(3216, A + b)
```

此处统一限幅指：积分项加入后仅保留3216限幅。没有修改两种算法的其他运算、输入或状态更新。

主问题 `SourceComparisonGoal` 对x、y任一轴、任意符号增益和输入满足原有 `InputGood`、`ReadAxis` 的实际调用，证明原始Csem返回存在；对于每个实际返回，通过真实全局字段、active返回类型/格式及对应向量字段观察实际积分和命令，并证明：

1. `-1429 <= b <= 1429`，实际算法的3216外层限幅不激活，故 `two=clip(1429,A)+b`。
2. `two=one` 当且仅当 `abs(A)<=1429`。
3. `A>1429` 时 `two<one`；`A<−1429` 时 `one<two`。
4. `abs(two-one)<=max(0,abs(A)-1429)`。

`ActualCounterexampleGoal` 构造两组真实合法内存及原始Csem调用：位置误差编码1280、kp=100，其余增益、速度、加速度、y轴和航向为0。第一组初积分为0，实际命令1429，统一参考2000；第二组合法初积分为−65536000，实际命令429，统一参考1000。第二组只声称该初始内存合法，不声称固定ki=0时从reset零积分达到它。

`UnconditionalEquivalenceRefutedGoal` 使用真实执行反例反驳原程序与统一限幅参考的无条件等价。

沿用原输入域：`in_flight=true`、缓存有效、`approx_force_by_thrust=false`、五个编码增益0..100、位置减法有符号安全、原速度/加速度/积分/航向范围、真实内存及ABI条件。主比较没有限定零前馈、零速度或具体增益；这些只用于存在性反例。原始执行模型没有裁剪或重生成，没有新增CBMC运行。问题的确切命题在 `Spec.v`，当前解答为 `../attempts/001/`。
